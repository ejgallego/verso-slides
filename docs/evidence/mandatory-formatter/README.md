## Implementation and application policy

`Config.virPrettyM`, `--pixel-pretty` and the conditional asset/publication paths
are removed. Normal `slidesMain` always prepares/publishes the owning libraries'
resources and installs the existing strict bootstrap. No pin, producer source,
runtime pack, recipe or shared contract changes occur.

`web-lib/panel/pretty.js` is now the single browser layer: the existing bounded
compact-to-host-ABI converter, DOM measurement, goal structure, annotation lookup,
escaping, binding selectors and reflow. The handwritten Lean layout port and
duplicate `web-lib/vir-prettym/pretty.js` are deleted. The converter/admission
behavior, independent complete ABI reference and native preflight/reservations
are retained. The role remains pure `formatSegments` / v2, returning typed
`Except FormatError (Array Pretty.Segment)`. Rich slide metadata remains JSON;
there is no JSON request/response formatting protocol.

Panels and lightboxes share `renderRichFormat`. It measures after inserting goal
structure, uses cell widths for types and content width for signatures, and releases
its probe in `finally` on success and failure. Monospace-space measurement converts
CSS pixels to columns with Reveal scaling. Invalid measurement is reported, with
no guessed space width or hardcoded lightbox width. Font notifications, resize and
current readiness reflow through this same renderer.

Every complete exact tag stack is retained in `data-format-tags`, including
unregistered tags and values beyond safe JavaScript integers. The nearest registered
tag still supplies visible class/binding. Text, names, prefixes, classes and binding
attributes are escaped; code/panel/lightbox binding selectors use `CSS.escape`.
Rejected expressions show a deliberate alert with raw diagnostic evidence;
pre-rendered layout does not substitute for a rejected rich format. Static messages
and documentation remain ordinary static content. Recoverable admission failures
leave the program active and a subsequent valid expression renders normally.

Historical pixel comparison code/results remain in commit history, including
[the retired formatter at 582de85](https://github.com/ejgallego/verso-slides/blob/582de85d9d7df0ac2c259404f913512656981d30/web-lib/panel/pretty.js).
The current browser comparison uses Lean/native complete results as its oracle.
